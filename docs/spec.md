# 카드 어드벤처 기획서 (v1.0 · 2026-11-12)

> 하트골드 스토리를 따라가는 **포켓몬 카드 가챠 + 슬레이 더 스파이어식 지도** 웹게임.
> 목적: 프론트엔드 취업 포트폴리오 겸 취미 프로젝트.
> 이 문서가 기획의 기준이다. 여기 적힌 **확정** 항목은 사용자 확인 없이 바꾸지 않는다.

---

## 0. 한 줄 요약과 참고작

- 몬스터볼 대신 **카드팩**으로 포켓몬을 얻는다. 전투 노드를 이기면 속성 팩을 고르고, 팩에서 나온 **5장을 전부** 가져간다.
- 하트골드의 **관장 22명**(성도 8 → 사천왕 4 → 목호 → 관동 8 → 레드)을 챕터 보스로 삼는다.
- 각 챕터는 **갈림길 지도**(야생 / 트레이너 / 엘리트 / 상점 / 휴식·강화 → 관장)로 진행한다.
- 같은 진화 계열 카드는 **자동으로 합쳐져 ★등급**이 오르고, 등급마다 받는 **개체값 포인트**를 직접 찍는다(최대 2V).
- 참고작: 포켓로그(웹 로그라이크), 포켓몬 어나더레드(스토리 + 난이도 선택), 올라라! 포켓몬 타워(층 선택 로그라이크), 슬레이 더 스파이어(지도 구조).

## 3. 챕터 지도

### 3.1 구조
- 일반 챕터는 **10층**. 1층은 출발 노드에서 2~3갈래, 아래에서 위로 진행한다.
- 같은 층 노드는 2~4개. 각 노드는 다음 층의 1~2개 노드와 연결되고, 선은 교차하지 않는다.
- **9층은 전부 휴식·강화**, **10층은 관장** 하나(슬레이 더 스파이어의 보스 직전 휴식 규칙).
- 지도는 `SaveData.seed + chapter`로 생성한다. 같은 세이브에서 같은 챕터를 다시 하면 같은 지도가 나온다.

### 3.2 노드 종류와 보상

| 노드 | 내용 | 보상 | 배치 규칙 |
|---|---|---|---|
| 야생 | 챕터 지역의 하트골드 야생 포켓몬 1마리 (§3.3) | 골드 소량 + 속성 팩 1개 | 어디든 |
| 트레이너 | 레벨대가 맞는 하트골드 원본 트레이너 (§3.4) | 골드 + 속성 팩 1개 | 어디든 |
| 엘리트 | 그 레벨대에서 가장 강한 원작 트레이너, 또는 라이벌 | 골드 많이 + **R 이상 확정** 팩 | 4층 이상 |
| 상점 | §6 | 없음 | 챕터당 1~2개, 3층 이상 |
| 휴식·강화 | 파티 회복 **또는** 카드 1장 레벨업(+[n]) 중 택1 | | 9층 고정 + 중간 0~1개 |
| 관장 | 원작 관장 파티 (§5.3 난이도 보정) | 배지 + **SR 이상 확정** 팩 + 기술머신 1개 | 10층 |

- 팩은 노드 보상 화면에서 **속성 18종 중 하나를 고른 뒤** 개봉한다.
- 노드 아이콘: 지역 배경 위에 이미지 + **노드 종류별 색 테두리**. 엘리트는 굵은 테두리와 "!" 배지, 관장은 크게 표시한다(§9).
  - 색: 야생 #5CC98B, 트레이너 #4FA3F7, 엘리트 #F2795A, 상점 #F2C14E, 휴식 #4FD1C5, 관장 #B27CF2

### 3.3 야생 포켓몬
- PokeAPI의 하트골드(`version`=heartgold) 출현 데이터(`encounters`, `location_areas`)로 챕터별 출현표를 자동 생성한다.
- 챕터별 지역은 `src/data/chapters.json`에 PokeAPI 지역 식별자로 정의한다. MVP 두 챕터는 다음과 같다.
  - 1장: `johto-route-29`, `johto-route-30`, `johto-route-31`, `sprout-tower/2f`, `sprout-tower/3f`
  - 2장: `johto-route-32`, `union-cave/1f`, `union-cave/b1f`, `johto-route-33`, `slowpoke-well/1f`
  - 챕터 레벨대에 맞지 않는 층(야돈의우물 지하 1층 Lv19~23, 어둠의동굴 지하 2층 Lv20~23)은 넣지 않는다.
  - 풀숲·동굴 출현만 쓴다. 낚시·파도타기와 라디오·대량발생 출현은 제외한다.
  - 설정은 `src/data/overrides/chapters.json`, 생성은 `scripts/build-chapters.mjs`.
- 레벨: 출현 데이터의 min~max 레벨에 난이도 보정(§5.3)을 더한다.

### 3.4 트레이너와 라이벌
- `scripts/build-trainers.mjs`가 하트골드 원본 트레이너를 추출한다: 보스·라이벌 70명 + 일반 트레이너 654명. 배틀프런티어 자리표시 데이터, 행인, 고유 인물은 제외. **직업(class)**도 저장해서 노드 이미지(§9)에 쓴다.
- 일반 트레이너는 개인 이름의 한국어가 없어 직업 이름으로 표시한다(`overrides/trainer-classes-ko.json`, 공식 명칭 대조 필요). 기술이 비어 있으면 원작처럼 레벨업 기본 기술을 쓴다.
- 원본에는 위치 정보가 없으므로, 파티 최고 레벨이 `(이전 관장 에이스 Lv, 이번 관장 에이스 Lv]` 범위인 트레이너를 그 챕터 풀로 쓴다.
- **라이벌**: 원본에 스타터별로 3종류 × 등장 시점별 파티가 있다. 레벨대로 챕터를 정해 엘리트 노드에 고정 배치한다.
  - 라이벌 스타터는 내 스타터에게 유리한 타입이다. 내가 풀이면 불꽃(브케인 계열), 불꽃이면 물(리아코 계열), 물이면 풀(치코리타 계열). 스타터 27종은 모두 풀, 불꽃, 물 중 하나다.

## 4. 카드 시스템

구현: `src/core/card.ts`, `src/core/gacha.ts` (테스트: `card.test.ts`)

### 4.1 카드팩
- 속성 팩: 해당 속성을 가진 종(쌍둥이 타입은 양쪽 팩 모두)에서 5장. 확률 N 60 / R 30 / SR 8 / UR 2.
  - `minRarity`가 있으면 그 등급 이상으로만 다시 정규화해서 뽑는다(엘리트 R, 관장 SR).
- 종 등급(`species.rarity`): 전설·환상은 UR, 종족값 합 500 이상은 SR, 400 이상이거나 진화체는 R, 나머지는 N.
- 스타터 팩: 27종 중 **서로 다른 5종** → 1장 선택. 챌린지 "랜덤 스타터"면 1장 무작위.
- **팩 카드 레벨**: 현재 챕터 야생 포켓몬의 최고 레벨(기본값, §12에서 조정 가능). 진화체가 진화 레벨보다 낮게 나와도 허용한다(원작 트레이너도 그렇다).

### 4.2 자동 합치기와 ★등급
- 보관함에는 **진화 계열(`lineId` = 계열의 첫 종)당 카드 1장**만 있다.
- 새 카드가 들어오면 같은 계열이 있으면 합치고, 없으면 NEW로 추가한다(`addToCollection`).
- ★n → ★n+1에 필요한 중복: **1 / 2 / 3 / 4장**. ★5까지 총 10장.
- 등급이 오를 때 개체값 포인트: **+8 / +10 / +12 / +16** (총 46).
- 합칠 때: 레벨은 높은 쪽, 기술은 합집합(`learnedMoves`), 장착 기술·개체값은 기존 카드를 유지한다.
- ★5 이후 중복은 골드로 환산한다(`MAXED_DUP_GOLD`, 현재 임시값 N 100 / R 200 / SR 500 / UR 1500).
- 팩 결과 화면에는 카드마다 `NEW` / `★2 → ★3` / `★4까지 1/3` / `+골드`를 표시한다.

> 근거: 게임 전체 팩 약 126개(챕터당 7개), 4속성 집중 기준으로 시뮬레이션하면 엔딩까지 ★5가 약 12계열, ★3 이상이 약 65계열이다. 속성을 무작위로 고르면 ★5는 거의 안 나온다. 그래서 팩 선택이 전략이 된다.

### 4.3 개체값
- 카드 획득 시 `ivBase`는 0~31 랜덤, 전투에는 `effectiveIvs = min(31, ivBase + ivAlloc)`를 쓴다.
- 포인트는 카드 상세 화면에서 +/−로 배분하고, 회수할 수 있다.
- **2V 상한**: 이미 31인 스탯이 2개 이상이면 다른 스탯을 31로 올릴 수 없다(30에서 멈춤).

### 4.4 기술
- `learnedMoves`: 레벨업(원작 레벨업 기술), 기술머신, 합친 카드에서 배운 기술의 합집합.
- `moves`: 그중 장착한 1~4개. 카드 상세 화면에서 언제든 교체한다.
- 레벨업으로 새 기술을 배우면 `learnedMoves`에 추가하고, 장착 칸이 비어 있으면 자동으로 장착한다.

### 4.5 경험치와 레벨
- 하트골드(4세대) 공식: `exp = floor(a × b × L / 7 / s)`
  - a: 트레이너전 1.5, 야생 1 / b: 쓰러뜨린 포켓몬의 `species.baseExp` / L: 쓰러뜨린 포켓몬 레벨 / s: 그 포켓몬과 싸운(전투에 나간) 아군 수
- 성장 곡선: `species.growthRate` → `src/data/expTable.json[곡선][레벨]` = 누적 경험치.
- 레벨 캡(어려움 이상)에 도달하면 경험치가 더 쌓이지 않는다.

### 4.6 진화
- 레벨업 진화: 원작 레벨.
- 진화의돌 진화: 상점에서 돌을 사서 카드 상세 화면에서 사용한다.
- 교환·친밀도·기타 조건 진화: **대체 레벨표**를 쓴다. PokeAPI `pokemon_evolution`에서 생성한다.
  - 기본 규칙: 교환 진화는 Lv36, 친밀도 진화는 Lv22. 그 외 조건은 같은 계열의 이전 진화 레벨 +10.
  - 결과는 `src/data/evolutions.json`, 수동 수정은 `src/data/overrides/evolution-levels.json`.
- 진화할 때 카드의 `speciesId`가 바뀌고 `lineId`는 그대로다.

### 5.1 현재 엔진 (완료)
- `battle(state, action, dex) → newState`: 순수 함수, 시드 RNG로 같은 입력이면 같은 결과.
- 원작 능력치 공식(노력치 0, 성격 무보정), 5세대 이후 데미지 공식(내림·0.5 반올림 원작 동일).
- 자속, 상성(무효 포함), 급소 단계, 랭크(능력치·명중·회피), 화상 반감, 우선도, 스피드(마비 1/2).
- 상태이상: 마비, 잠듦, 얼음, 화상, 독, 맹독, 혼란, 풀죽음, 타입 면역.
- 기술 효과: 능력치 변화, 흡수, 반동, 회복, 연속기, 일격필살, 발버둥, 위력 가변 기술 23종 + 소닉붐·용의분노·사이코웨이브·매그니튜드. (은혜갚기·화풀이는 친밀도가 없어 미구현)
- 쓰러짐: 상대는 자동 교체, 플레이어는 `pendingSwitch`.
- 로그 조사 자동 처리(`fixJosa`): "갸라도스는", "리자몽을".

### 5.2 추가할 것
1. **연출용 이벤트 출력**: `log: string[]` 외에 `events: BattleEvent[]`를 추가한다. UI는 이벤트를 하나씩 재생하며 HP 바 감소, 피격 깜빡임, 기절 연출을 붙인다.
   ```ts
   type BattleEvent =
     | { type: 'switchIn'; side: Side; idx: number }
     | { type: 'move'; side: Side; moveId: string }
     | { type: 'damage'; side: Side; from: number; to: number; effectiveness: number; crit: boolean }
     | { type: 'heal'; side: Side; from: number; to: number }
     | { type: 'status'; side: Side; ailment: Ailment }
     | { type: 'stage'; side: Side; stat: BattleStat; delta: number }
     | { type: 'faint'; side: Side }
     | { type: 'message'; text: string };
   ```
2. **가방 아이템 사용**: 전투 행동 `{ kind: 'item'; itemId; targetIdx }`. 트레이너 AI는 원본 `bagItems`를 원작처럼 HP가 낮을 때 사용한다.
3. **지닌 도구** 효과(초기 10개, §6).
4. **난이도별 AI**(§5.3).
5. **경험치 지급**과 레벨업, 기술 습득, 진화 체크는 전투 종료 후 처리한다(엔진 밖 `progress.ts`).
6. **미구현 변화기** 중 자주 쓰이는 것부터: 방어, 판별, 잠자기, 날개쉬기, 대타출동, 스텔스록, 압정뿌리기, 날씨 4종, 씨뿌리기, 조이기류.

|---|---|---|---|---|
| 상대 레벨 | 원작 −2 | 원작 | 원작 +3 | 원작 |

## 7. 저장

- `SaveData` 타입(`src/core/types.ts`)이 세이브 1개다. JSON으로 직렬화한다.
- localStorage 키: `card-adventure:slot:1~3`. 자동 저장 시점: 노드 완료, 상점 구매, 카드 편성 변경.
- **세이브 파일 내보내기/불러오기**(JSON 다운로드·업로드)를 타이틀 화면에 둔다. Safari는 7일간 방문이 없으면 데이터를 지울 수 있어서 백업 수단이 필요하다.
- 앱 시작 시 `navigator.storage.persist()`를 요청한다.
- `version` 필드로 마이그레이션한다. 저장소 접근은 `src/store/saveRepository.ts` 한 곳으로 모아서, 나중에 클라우드(Supabase)로 바꿀 수 있게 한다.
- **진행 중이던 노드는 저장하지 않는다.** 전투 도중에 닫으면 그 노드에 들어가기 전으로 돌아간다(같은 노드를 반복해 보상을 얻지 못하게).
- 이긴 뒤 **열지 않은 보상 팩**과 **관장 클리어 대기**는 저장해서, 불러오면 그 화면부터 이어진다. 스타터를 고르기 전에 닫아도 같은 5장이 남는다.
- 자동 저장은 상태가 바뀌면 0.4초 모았다가 하고(노드 완료·상점 구매·편성 변경 포함), 플레이 시간은 30초마다, 창을 닫거나 숨길 때는 바로 한다.
- 너즐록 게임 오버가 되면 그 자리에서 세이브를 지운다.

## 11. 로드맵

각 단계는 테스트 통과와 `npm run build` 성공으로 마친다.

1. **프로젝트 구성**: 현재 폴더에 Vite + React + TS. 기존 `src/core`, `src/data`, `scripts` 유지. Tailwind, Zustand, Framer Motion, Vitest. `.gitignore`에 `public/assets/**` (단 `.gitkeep` 제외).
2. **엔진 보강**: `BattleEvent` 출력, `progress.ts`(경험치·레벨업·진화), `evolutions.json` 생성.
3. **데이터 확장**: 원본 트레이너 전원 + 직업, `chapters.json`(1~2장), 하트골드 야생 출현표, `tmCompat.json`.
4. **전투 화면**: DS풍 UI, 이벤트 재생 연출, 스프라이트 대체 로직. 테스트 화면에서 비상과 대결할 수 있게.
5. **카드 화면**: 스타터 팩, 속성 팩 개봉, 보관함, 카드 상세(포인트, 기술 장착).
6. **지도**: `map.ts` 생성 규칙, 지도 화면, 노드 → 전투·팩·상점·휴식 흐름.
7. **저장**: 슬롯 3개, 자동 저장, 내보내기/불러오기, 타이틀과 새 게임 화면.
8. **MVP 완성**: 1~2챕터 통으로 플레이, 난이도 4종, 밸런스 조정, Vercel 배포, README(설계 문서, 시연 GIF).
9. 이후: 3~22챕터 데이터, 미구현 변화기, 지닌 도구, 대사, 모바일, 클라우드 저장.
